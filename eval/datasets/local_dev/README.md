# Local development suite v1

`cases.py` creates 30 bilingual cases: **10 query families × 3 region parameters**.
These are development/regression cases, not a representative or held-out Vietnamese benchmark.
They overlap conceptually with the five existing seed questions. Keep all region variants of
a family together if a future dataset is split. Do not randomly split these 30 rows and call
the result generalization to unseen query structures.

- Authoring: AI-assisted in the 2026-09-29 coding session; no external dataset.
- Human review: pending. Separate Python code is a cross-check, not an independent annotator.
- Database: synthetic data generated by `db/seed.py`; English 12-table schema.
- Time: explicit calendar dates; no CURRENT_DATE or unimplemented relative-time resolver.
- Scope: scalar aggregates, status/boolean filters, quantity versus count, distinct counts,
  thresholds and joins, including one six-join family. Not a test of ranking, output ordering,
  ambiguous questions, paraphrases, natural-language understanding, or retrieval.
- Revenue: sum succeeded payments using paid_at in Q2 2026, rounded to two decimals.
  Other question definitions are explicit; they are not claims of universal business semantics.
- Oracles: Python loops/sets and integer-cent monetary accumulation in `oracles.py`.
  They read generated rows, never the gold SQL or SQL results.
- Mutations: one deliberately wrong query per case (10 mutation templates, parameterized
  across regions). SQL must execute and pass policy but fail both result comparators.
- Snapshots: RNG seeds 20260727 and 20260728. These are two datasets from one generator,
  not independent real-world databases. Changing seed does not repair generator bias.

Run `python -m eval.harness.local_validation` from the repository root. Exported questions,
gold SQL, mutation SQL, per-case results, provenance hashes and summary stay in git-ignored
`eval/results/`. The runner does not open `data/dev.sqlite`, use `.env` database connections,
or call a model provider. Inherited data anomalies are counted in every report.

The correct result label is **gold-SQL validation / semantic mutation detection**.
It is never Text-to-SQL model execution accuracy.
